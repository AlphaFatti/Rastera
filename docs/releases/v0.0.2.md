## Build and delivery

Apple silicon **arm64 only**, not Universal; minimum **macOS 14.0**, required by the native CAMetalDisplayLink path. `LC_BUILD_VERSION` is inspected and must match `LSMinimumSystemVersion`. Actually tested: Apple M1 Pro, macOS 15.5. Other chips/OS versions and another Mac are pending. `lipo` and `otool -L` must show arm64 and only system dependencies. Shaders/fonts are embedded; notices are copied into Resources. No Rust/Cargo/Python/Homebrew/ffmpeg/checkout/developer variables are needed by the installed executable. Python/Cargo/ffmpeg used by build/test drivers are not runtime dependencies.

From a clean committed release checkout with the repository's pinned Rust/tool dependencies:

```sh
cargo fmt --all -- --check
cargo check --workspace --locked
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
python3 -m unittest discover -s tools -p 'test_*.py'
cargo build --release --workspace --locked
./tools/build-app.sh --dmg
(cd target/dist && shasum -a 256 -c SHA256SUMS)
```

`build-app.sh` and `package_app.py` remain the single bundle-generation path. `--dmg` rejects dirty Git revisions and installation flags; use `--dist-dir=/absolute/fresh/directory` for another build. In-repository distributions must be under ignored `target/`. Local `--install` is unchanged and deliberately not run for release verification, preserving the user's installation/profile/viewport recall.

Default `target/dist/` files:

- `Rastera-0.0.2-macOS-arm64.dmg`: UDZO compressed read-only image; app, `/Applications` shortcut and `Tester Guide.txt` only.
- `Rastera-0.0.2-Tester-Guide.txt`: identical guide alongside the image.
- `Rastera-0.0.2-macOS-arm64-Build-Info.json`: source commit, version/architecture/minimum OS, clean-tree flag, signing and actual Gatekeeper assessment.
- `SHA256SUMS`: final DMG/guide/build-info digests after signing/stapling.

The bundle records its exact clean release source commit in Info.plist and Resources/build-info.json. Payload allowlisting excludes projects, recordings, recovery, preferences, device patches, logs and credentials; no demo is included. Generated binaries remain outside Git history.

## Signing and first launch

This machine has **zero valid Developer ID Application identities** and no configured distribution/notary profile. The delivered preview is **ad-hoc signed and unnotarized**. Camera/audio-input usage strings, entitlements, hardened runtime and bundle identity `org.rastera.desktop.dev` are preserved. Strict codesign integrity verification is separate from Gatekeeper acceptance; a downloaded/quarantined preview is expected to require a per-app exception.

The existing `RASTERA_SIGN_IDENTITY` applies only to local development packaging. Distribution `--distribution-signing=auto|adhoc|developer-id` independently uses a valid `RASTERA_DISTRIBUTION_IDENTITY` (certificate name/hash) and `RASTERA_NOTARY_PROFILE` (preconfigured keychain profile). Auto chooses Developer ID only with one matching valid identity and a profile; otherwise it produces an explicitly labelled ad-hoc preview. Explicit developer-id mode fails closed without them. The configured path requests secure timestamps, submits app ZIP and DMG with notarytool, inspects Accepted/logs, staples/validates app and image, and requires final Gatekeeper assessment. That credential-dependent path is not exercised on this machine; mocked selection tests are not notarization evidence. No passwords or credentials are bundled.

Tester instructions use Apple's supported **System Settings → Privacy & Security → Open Anyway** per-app path after a trusted app's blocked first launch. Do not disable Gatekeeper globally or strip quarantine as a release procedure. Managed policy can prevent the exception; malware/damage alerts require investigation. [Apple's opening instructions](https://support.apple.com/en-us/102445), [notarization workflow](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow).
